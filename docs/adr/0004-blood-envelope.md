# ADR-0004: Кровь роя — конверт состояния с допуском, цепью и ttl

- Статус: принято
- Дата: 2026-11-08
- Контекст: контур сверки (ADR-0002) живёт внутри одной клетки. Между клетками
  роя (геном cell-swarm ↔ клетка runtime-protocol ↔ клетка polymath-os) состояние
  до этого момента переносилось только событием `cell-pushed` (пин догоняется
  геномом). Ворклог TH-RTP-05 (H-PE11-PHOENIX).

## Проблема

Клетки не обмениваются состоянием — геном перерисовывает пины, но рой не имеет
кровообращения: живой факт о клетке (что желают / что наблюдают / в допуске ли)
не течёт от тела к телу. Расписание для этого строить нельзя (закон 1: угадчик —
это яд), а голый `repository_dispatch` без структуры переносит нарратив, а не факт.

## Решение

Кровь = конверт (`blood.py`), у которого сверка вшита в структуру, а не обещана:

1. **Допуск в конверте.** `payload.tol = {eps, deadband}` — конверт сам говорит,
   что считать совпадением. Двухступенчатый допуск наследует ADR-0002: мёртвая
   зона (не дёргаемся) / внутри eps (VERIFIED) / за eps (DRIFT — факт дрейфа
   тоже несётся кровью, это не ложь).
2. **Хеш-цепь.** Каждый конверт содержит `sha256` канонического JSON предыдущего
   конверта летописи (`prev_hash`), genesis = 64 нуля. Летопись
   `cell-swarm/blood/LEDGER.jsonl` — tamper-evident (паттерн Rekor/Trillian):
   подмена или удаление любой середины ловится сверкой хешей.
3. **ttl.** `ttl_s` (по умолчанию 900) — просроченный конверт не верифицируют:
   скорость сверки обязана быть больше скорости изменения территории.
4. **Транспорт — событие, не таймер.** Кровь течёт по `repository_dispatch`
   (blood-pulse) и по факту эха. Единственный носитель для cross-repo вызова —
   секрет `CELL_SWARM_DISPATCH_TOKEN` (токен = кровь-носитель, ротация —
   docs/ROTATION.md).
5. **Эхо = факт, не нарратив.** Клетка отвечает конвертом с `observed` (живой
   github.sha), `expected`, `status` — верифицируемыми полями, которые геном
   может пересчитать сам.

## Следствия

- Пульс роя = цепочка: геном (или рука владельца) → клетка A → клетка B →
  летопись. Каждый шаг оставляет хеш-скреплённую запись.
- `blood_cell.py` идемпотентен: повторная доставка конверта даст STALE (ttl) или
  честное новое эхо, дубли в летописи невозможны (seq строго растёт по паре
  src→dst).
- Летопись — файл, а не сервис: она читается git-ом, проверяется офлайн
  (`chain_verify`), и её целостность — приёмка, а не обещание.
- Кровь не заменяет пин-геном: пин = ЖЕЛАЕМОЕ, кровь = перенос НАБЛЮДАЕМОГО,
  эхо = ДЕЙСТВИЕ клетки. Три ноги контура сверки между телами.

## Приёмки

`test_blood.py` — 17 приёмок: каноничность байтов, склейка/подделка/просрочка
конверта, разрыв цепи, монотонность seq, мёртвая зона, допусковая гистерезис,
дискретный SHA, tamper-evident летописи (подмена и удаление середины).
`make verify` клетки: 22 → 39 приёмок, fail-closed.
